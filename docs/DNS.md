# DNS в Yoru

В разделе **DNS** настройте основные серверы, режим разрешения и правила для отдельных доменов.

## DNS для отдельных доменов

Нажмите **Настроить** напротив «DNS для отдельных доменов». Каждая строка связывает домен с DNS-сервером:

| Домен | Действие |
|---|---|
| `company.example` | Только точное имя |
| `+.company.example` | Имя и все его поддомены |

Домен вводится без `https://` и пути. В поле DNS укажите IP, IP:порт или DNS URL, например `10.20.0.53`, `10.20.0.53:53` или `https://dns.quad9.net/dns-query`. Несколько DNS для одного домена задаются строками с одинаковым доменом. Список сохраняется кнопкой **Сохранить**; пустой список использует общие DNS.

## Fake-IP и реальные адреса

**Fake-IP** возвращает приложениям виртуальные адреса, по которым Mihomo определяет исходные домены. **Redir-host** возвращает реальные IP. Исключения Fake-IP позволяют получать реальные адреса для отдельных доменов при включённом Fake-IP.

## Cisco Secure Client / AnyConnect

Когда Yoru и Cisco работают одновременно, корпоративный DNS может уходить через физическую сеть или туннель Yoru вместо интерфейса Cisco. Рабочие домены при этом могут не разрешаться или отвечать с задержкой. Для DNS рабочих доменов укажите **адрес DNS-сервера**, полученный от Cisco, и закрепите его за интерфейсом: `IP#имя_интерфейса` (Yoru 1.4.1+). IP виртуального адаптера Cisco не обязательно является DNS-сервером. Имя интерфейса Yoru не определяет автоматически.

1. Подключите Cisco. Найдите выданные им DNS, интерфейс и маршруты к рабочим сетям. На Windows выполните в PowerShell:

   ```powershell
   Get-NetAdapter | Format-Table Name,InterfaceDescription,Status
   Get-DnsClientServerAddress -AddressFamily IPv4 | Format-Table InterfaceAlias,ServerAddresses
   ```

   Сопоставьте DNS с адаптером Cisco по `InterfaceAlias` и описанию. Его имя может отличаться от `Ethernet 2`.

   На macOS при подключённом Cisco, до запуска TUN Yoru, проверьте `scutil --dns` и маршрут к найденному DNS:

   ```sh
   scutil --dns
   route -n get 192.0.2.53
   ```

   Замените `192.0.2.53` на адрес своего DNS. В выводе маршрута нужен интерфейс Cisco, часто `utunN`; при сомнении сопоставьте его с адресом клиента через `ifconfig -a`. После переподключения Cisco номер `utun` может измениться.

2. В **Правила → Добавить набор** создайте набор рабочих ресурсов. Заполните вкладки **Домены**, **DNS** и **IP и подсети**. Пример значений:

   | Поле | Пример |
   | --- | --- |
   | Домены | `+.company.example` |
   | DNS на Windows | `192.0.2.53#Ethernet 2` |
   | DNS на macOS | `192.0.2.53#utun7` |
   | IP и подсети | `198.51.100.0/24` |

   `.example` и показанные IP-диапазоны — документационные заглушки. Замените их доменами, DNS и **точными** подсетями своей компании, а суффикс после `#` — реальным именем интерфейса на этом устройстве. Если DNS несколько, добавьте каждый отдельной строкой. DNS набора применяется к его **доменам**; вкладка **IP и подсети** задаёт маршруты к адресам, а не DNS для них.

3. Выберите маршрут **Напрямую**, включите **Реальные IP для доменов** и **Обход TUN**. Обход TUN исключит подсети набора и IP его DNS из виртуального адаптера Yoru: они пойдут по маршрутам ОС, которые должен установить Cisco. Поднимите набор выше общих правил **Через VPN** и включите на странице **Статус** режим **По правилам**. DNS-политика и исключения TUN действуют вне порядка правил; при изменении исключений может потребоваться перезапуск ядра.

4. Проверьте рабочий домен и HTTPS при подключённых Cisco и Yoru, затем обычный сайт, который должен идти через Yoru. Одного ответа из DNS-кеша недостаточно. Если маршрут к корпоративному DNS не ведёт в Cisco или у Cisco нет маршрута к рабочей подсети, правило Yoru это не исправит.

Домен шлюза Cisco должен разрешаться **до** подключения Cisco. Не направляйте его начальный DNS-запрос на сервер, доступный только внутри корпоративного туннеля. Если шлюз попадает в широкий рабочий доменный суффикс, задайте для него отдельное разрешение и прямой маршрут.
