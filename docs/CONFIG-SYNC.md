# Синхронизация полной конфигурации по HTTPS

В **Настройки → Синхронизация по URL** пользователь вставляет персональный HTTPS URL и одним нажатием **Загрузить и заменить** получает полную конфигурацию. Ссылка сохраняется локально для следующего ручного обновления. Фоновая синхронизация полной конфигурации не запускается; обычные подписки обновляют серверы по своим интервалам.

## Контракт endpoint

Ответ `200 OK` содержит обычный JSON `core.Config`, не YAML подписки и не обёртку резервной копии. Рекомендуемый Content-Type: `application/json`. Максимальный размер: 2 МиБ. Обязательные верхние поля: `servers`, `selected`, `rules`, `sets`, `routeOrder`, `subscriptions`, `dns`, `settings`, `defaultAction`. Пустые списки передаются как `[]`, а не `null`. `logging` и `tunOptions` поддерживают штатные значения по умолчанию.

`servers` содержит готовые записи серверов в формате Yoru. Вставка subscription URL в пустую конфигурацию сама по себе не загружает узлы. `selected` ссылается на существующий server ID или пустую строку. Каждое правило и набор имеют уникальный непустой ID. `routeOrder` содержит каждую запись ровно один раз: `{"kind":"rule","id":"rule-id"}` или `{"kind":"set","id":"set-id"}`. Порядок сохраняется. Неверные, повторные и пропущенные ссылки отклоняются до нормализации.

Остальные поля проходят общую проверку `Config.Validate`: серверы и их параметры, режимы, DNS, интервалы подписок, правила и настройки групп. `revision` сервера игнорируется; применяется текущая локальная ревизия. `configSyncURL` из ответа игнорируется; источником остаётся URL, который ввёл пользователь.

Разрешён только HTTPS без логина, пароля и fragment. Редиректы разрешены только на тот же host и port по HTTPS, не больше четырёх переходов. Запрос ограничен 30 секундами. Ошибки HTTP показывают только код; сетевые ошибки и содержимое ответа не выводят персональный URL в интерфейс или журнал.

## Применение и восстановление

Загрузка выполняется без блокировки локальных операций. Если локальная ревизия изменилась за время загрузки, импорт отменяется с предложением повторить синхронизацию. До применения записывается закрытая резервная копия `config-before-url-sync.json` в папке настроек Yoru. Неудачная запись копии отменяет импорт. Копия имеет формат штатного JSON-импорта и обновляется при следующей синхронизации.

Серверы, подписки, правила, наборы, их общий порядок, DNS, параметры группы и маршрутизации заменяются целиком. Настройки устройства сохраняются: TUN, системный прокси, автозапуск, запуск свёрнутым, автоподключение, трей, `tunOptions.interface` и `tunOptions.autoDetect`. Это позволяет переносить конфигурацию между Windows и macOS без удалённого изменения привязки адаптера и разрешений ОС. Заданные в DNS имя интерфейса и правила по пути процесса всё ещё должны соответствовать целевой ОС.

Применение использует общую транзакцию `SaveLive`: работающему ядру обновляются маршруты без перезапуска TUN, а ошибка применения или сохранения восстанавливает прежние параметры. Изменения адаптера могут ожидать явного перезапуска, о чём сообщает существующий индикатор. После успешного применения локальный JSON заменяется атомарно. Восстановление: **Настройки → Импорт настроек**, выбрать `config-before-url-sync.json`.

Персональная ссылка хранится в локальном `config.json` и входит в последующие резервные копии. Не публикуйте ссылку, конфигурацию и копии: они содержат доступ к VPN.
